# AI Linux SysAdmin Agent

[![Validate](https://github.com/joaocastanheira-it/ai-linux-sysadmin-agent/actions/workflows/validate.yml/badge.svg)](https://github.com/joaocastanheira-it/ai-linux-sysadmin-agent/actions/workflows/validate.yml)

AI-assisted Linux system health monitoring and troubleshooting tool built with Bash.

The project collects system metrics, classifies resource usage, produces machine-readable JSON reports, and can use the OpenAI API to generate concise troubleshooting recommendations.

## Features

* Display Linux system information and uptime
* Monitor memory and root filesystem usage
* Classify results as `OK`, `WARNING`, or `CRITICAL`
* Return automation-friendly exit codes
* Generate structured JSON output
* Save timestamped JSON reports
* Analyze system health using the OpenAI API
* Support configurable warning and critical thresholds
* Validate Bash syntax and code quality through GitHub Actions
* Provide clear errors for missing commands or configuration

## Requirements

The basic health check uses standard Linux utilities:

* Bash
* `free`
* `df`
* `awk`
* `hostname`
* `uptime`

AI analysis additionally requires:

* `curl`
* `jq`
* An OpenAI API key

ShellCheck is recommended for local development.

### CentOS, Fedora or RHEL

```bash
sudo dnf install curl jq ShellCheck
```

### Ubuntu or Debian

```bash
sudo apt update
sudo apt install curl jq shellcheck
```

## Installation

Clone the repository:

```bash
git clone https://github.com/joaocastanheira-it/ai-linux-sysadmin-agent.git
cd ai-linux-sysadmin-agent
```

Make the script executable:

```bash
chmod +x health_check.sh
```

## Usage

### Run the standard health check

```bash
./health_check.sh
```

### Show help

```bash
./health_check.sh --help
```

### Show the current version

```bash
./health_check.sh --version
```

### Produce JSON output

```bash
./health_check.sh --json
```

Example:

```json
{
  "timestamp": "2026-09-04T15:17:35+01:00",
  "hostname": "MylinuxVM",
  "memory": {
    "usage_percent": 77,
    "status": "OK"
  },
  "disk": {
    "usage_percent": 42,
    "status": "OK"
  },
  "overall_status": "HEALTHY",
  "exit_code": 0
}
```

### Save a timestamped report

```bash
./health_check.sh --save
```

Example:

```text
Report saved to: reports/health_20260904_151735.json
```

Generated reports are stored under `reports/` and excluded from Git through `.gitignore`.

A different report directory can be selected with:

```bash
REPORT_DIR=/var/tmp/health-reports ./health_check.sh --save
```

## AI analysis

The `--analyze` option sends the generated health report to the OpenAI Responses API and prints a concise analysis.

```bash
./health_check.sh --analyze
```

The AI receives only the system-health JSON generated by the script. It does not access the machine directly or execute commands.

### Configure the API key

Create an API key at:

```text
https://platform.openai.com/api-keys
```

Configure it securely for the current terminal session:

```bash
read -rsp "OpenAI API key: " OPENAI_API_KEY
export OPENAI_API_KEY
echo
```

Confirm its presence without displaying the secret:

```bash
if [[ -n "${OPENAI_API_KEY:-}" ]]; then
    echo "API key configured"
else
    echo "API key missing"
fi
```

Never store an API key in the script or commit it to Git.

The default model can be overridden through `OPENAI_MODEL`:

```bash
OPENAI_MODEL="gpt-5.6-luna" ./health_check.sh --analyze
```

OpenAI API usage may require separate billing and is not included automatically with a ChatGPT subscription.

## Configurable thresholds

The default resource thresholds can be overridden with environment variables.

```bash
MEMORY_WARNING=70 \
MEMORY_CRITICAL=85 \
DISK_WARNING=75 \
DISK_CRITICAL=90 \
./health_check.sh
```

This makes it possible to adapt the checks to different servers and workloads without editing the script.

## Exit codes

| Code | Meaning                                          |
| ---: | ------------------------------------------------ |
|  `0` | System healthy                                   |
|  `1` | Warning detected                                 |
|  `2` | Critical condition detected                      |
| `64` | Invalid command-line option                      |
| `69` | Required command or external service unavailable |
| `70` | Invalid or empty API response                    |
| `73` | Report file or directory could not be created    |
| `78` | Required configuration is missing                |

Example:

```bash
./health_check.sh
exit_code=$?

if (( exit_code == 2 )); then
    echo "Critical system condition detected"
fi
```

## Automated validation

GitHub Actions validates every push and Pull Request targeting `main`.

The workflow:

1. checks out the repository;
2. validates Bash syntax with `bash -n`;
3. analyzes the script with ShellCheck.

Workflow configuration:

```text
.github/workflows/validate.yml
```

## Security

* API keys are read from environment variables
* Secrets are not stored in the repository
* Generated health reports are excluded from Git
* AI recommendations are informational and are never executed automatically
* Destructive commands are explicitly discouraged in the model instructions
* System changes should always be reviewed by an administrator
